Installation of Splunk Enterprise:

Installing Splunk came with a variety of small challenges that I had to overcome, but for the most part was fairly straightforward. I began by installing Splunk Enterprise from my host laptop, but then I had to find a way to get it on my Ubuntu VM. To do this, I needed to utilize scp to get the download file of Splunk from my host laptop downloads folder to my Ubuntu VM. However, since I only set up a NAT Network for the various VMs to communicate on, there was not yet a way for my host laptop to actually communicate with the VMs. So, I set up a secondary network for the Ubuntu VM where it was a host-only adapter, allowing me to get a second IP address associated with this network that I could successfully scp the Splunk File into the Ubuntu VM. With the file now in Ubuntu, I had to properly install it. The install itself was easy through dpkg (Debian Package, which allows for the install of .deb files), but starting Splunk was the harder part. At first, I just tried to sudo and start splunk through the /opt/splunk/bin/splunk path, but this ended up being a deprecated way of starting Splunk. So, I utilized AI to help guide me through the newer version starting process, and it allowed me to update ownership of the entire /opt/splunk path to splunk:splunk, and then I started splunk without sudo because there was no longer ownership issues, and it started up after I accepted the license. I chose a username and password for splunk, and after it started up, I ensured it was running by checking the status of /opt/splunk/bin/splunk and I also set up splunk to start up at boot to save me time. Then, I opened Splunk Web by utilizing the IP address of the secondary host-only adapter network, and got into Splunk Web without an issue. The interface seemed intuitive, but since I've only installed it so far, a lot of the functionality and overall use of Splunk Web is still very unknown to me. I look forward to exploring it further as I progress with the project. Lastly, I configured Splunk to receive forwarded data by changing the settings within Splunk Web, and set a new receiving port to 9997, allowing it to receive data from the Splunk Universal Forwarder in the future. I confirmed that Splunk was listening on TCP port 9997, which is correctly was. The Splunk version I am using is 10.4.1 for Linux, and overall I'm happy that I got some tangible results from this phase, as actually getting into Splunk Web felt like a big accomplishment. 



Installation of Splunk Universal Forwarder:

With Splunk now installed, downloading the universal forwarder was easy. I logged on to the Windows 11 VM (meant to act as the "victim"), and downloaded Splunk Universal Forwarder for Windows 64 bit. After this, I simply ran the file and had to enter in the IP address and port to listen to, and the Splunk Universal Forwarder was all set up. Then, I configured an inputs.conf file which configured Windows event log collection, and I put in Application logs for software events, Security logs for authentication, logins, and auditing, and lastly System logs for OS events. With all of this configured, I could now recieve logs on Splunk Web and view them. So, the Splunk Universal Forwarder being properly setup will allow me to collect and analyze logs from my victim VM by viewing the logs on Splunk Web.
